1. Quais referências mudam quando a nova página é inserida?
R: Se a lista estiver vazia: inicio, fim e atual passam a apontar para o novo nó.Anterior e proximo = none.
Se inserida a partir da página atual (atual existe):
O novo nó passa a ter anterior = atual e proximo = None.
atual.proximo passa a apontar para o novo nó.
Como a navegação descarta as páginas à frente ao visitar uma nova URL, o novo nó torna-se o novo fim da lista.
O ponteiro atual é atualizado para o novo nó.

2.Por que o histórico à frente deve ser removido após uma nova navegação?
R: Em um navegador real, ao voltar 2 páginas e acessar um site novo, a linha do tempo "ramifica". O navegador adota a convenção de descartar as páginas futuras da sessão antiga para manter o histórico estritamente linear em relação à nova sequência de navegação.

3.Quando inicio, fim e atual apontam para o mesmo nó?
R: Quando o histórico possui exatamente uma página (uma única URL visitada na sessão).

Atividade 2 -
Antes de programar
1. Quantas ligações podem mudar ao remover um nó do meio?
R:Podem mudar até 4 ligações (referências de ponteiro) no total:
- anterior.proximo: O ponteiro de próximo do nó anterior passa a apontar para o nó seguinte.
- proximo.anterior: O ponteiro de anterior do nó seguinte passa a apontar para o nó anterior.
- no_removido.proximo: É limpo (None) para isolar o nó removido da lista e evitar vazamento de memória/referências cruzadas.
- no_removido.anterior: Também é limpo (None) pelo mesmo motivo.

2. Como reconhecer a remoção da primeira ou da última música?
R:Primeira música (inicio):
O nó a ser removido possui anterior == None (ou no == self.inicio).
Tratamento: O ponteiro self.inicio da lista deve ser atualizado para apontar para no.proximo.

Última música (fim):
R:O nó a ser removido possui proximo == None (ou no == self.fim).
Tratamento: O ponteiro self.fim da lista deve ser atualizado para apontar para no.anterior.

Única música na playlist:
R:O nó possui tanto anterior == None quanto proximo == None (ou self.inicio == self.fim == no).
Tratamento: Ambos os ponteiros da lista (self.inicio e self.fim) passam a ser None.

3. Por que mover um nó não exige copiar todos os seus dados?
Porque a lista encadeada trabalha com alocação dinâmica por referências (endereços de memória) e não por cópia física de valores.
Ao mover uma música (por exemplo, transferir o nó do final para o início), todos os seus atributos (codigo, titulo, artista, duracao) continuam intactos no mesmo objeto na memória.
Você só precisa desconectar 2 ou 3 ponteiros de onde o nó está atualmente e reconectar esses ponteiros no início da lista

3. Por que o percurso inverso ajuda a testar a estrutura?
R:O percurso inverso (do fim para o inicio usando o ponteiro anterior) é fundamental para validar a integridade dos ponteiros de volta:Detecta ponteiros quebrados/nulos: Se ao inserir ou reagendar um nó esquecermos de atualizar o ponteiro anterior (por exemplo, deixando B.anterior apontando para $A$ em vez de $N$), a listagem direta funcionará normalmente, mas a listagem inversa pulará nós ou causará um erro de ponteiro nulo (NullPointerException / Segmentation Fault).Valida o ponteiro fim: Garante que a referência da cauda da lista está realmente apontando para o último elemento cronológico.

Atividade 4 - 
1. Qual condição indica que uma volta completa terminou?
R:A volta completa termina quando o ponteiro auxiliar de navegação retorna ao ponto de partida (aux.proximo == inicio ao inspecionar o próximo nó, ou quando aux == inicio após ter avançado pelo menos uma vez a partir do início).2. O que deve acontecer com fim-&gt;prox quando inicio muda?
R:O ponteiro fim.proximo deve ser imediatamente atualizado para apontar para o novo nó inicio, preservando o invariante da lista circular de que o último nó sempre aponta para o primeiro.
3. Como atualizar atual quando o jogador atual é removido?
R:O ponteiro atual deve ser redefinido para o nó imediatamente posterior ao jogador removido (no_removido.proximo). Caso o jogador removido fosse o único restante na lista, atual passa a ser None.
